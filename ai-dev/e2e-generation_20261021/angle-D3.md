## Resolution

**(a) Durable CI suite runtime: no clear winner. The deciding factor is whether current Detox works on this app, which only a local spike can show.**

- The strongest new evidence is against Maestro **on this exact toolchain**. #3538 is open, matches Xcode 26.3–26.6 and iOS 26.2–26.5, and reproduces on every release through 2.11.0. Its symptom (the driver dies and every remaining flow fails) matches the local crash every 2–4 runs. The maintainers' fix is a driver rework that has not shipped (E22–E25). Upgrading past 2.6.0 brings real iOS fixes in 2.7.0 (E24) but no fix for this failure class. #1585 is a red herring: it is closed and unfixed, and is not the current tracking issue.
- Detox is maintained on iOS 26 (C3). But the iOS-26-capable releases (≥20.47, about Jan 2026) target RN 0.77–0.84. RN 0.72.17 is "do our best" territory, and nothing shows the two working together (C4). Worker A1's caveat holds, and it is the binding unknown.
- **Decision rule.** Choose Detox as the CI runtime only if a spike shows that (1) Detox ≥20.51.x builds and runs on RN 0.72.17 for both iOS 26.5 and Android, and (2) the app idles under Firebase listeners without blanket `disableSynchronization`. Otherwise choose Maestro, with these mitigations:
  - pin a version ≥2.7.0
  - run one flow per invocation, with a driver/simulator reset-and-retry wrapper
  - set `MAESTRO_DRIVER_STARTUP_TIMEOUT`
  - track #3538 and the driver rework, and re-evaluate when it ships
- If the RN 0.72 → ≥0.77 upgrade is planned anyway, Detox's case gets much stronger, because the app would then be inside Detox's supported window.

**(b) Exploration and authoring tool: Maestro MCP (Worker A1 and A5 agree, and the evidence supports them).** It is the only option found with agent-native screen inspection plus run (C11). Pilot runs tests at runtime and is not a code generator (C12). Operating constraints come from open MCP bugs (C10):

- use one `maestro mcp` process per simulator
- restart it after any erase or reboot
- never run two simulators behind one MCP server

**Coexistence (Q5).** No precedent was found for compiling one spec into both runners. Coexistence looks cheap in principle (the same RN `testID`s would drive both), but the Maestro `id:` ↔ RN `testID` mapping was not fetched here (gap). A workable hybrid: Maestro MCP for exploration, then the LLM emits Detox TS from the explored flow plus testIDs. That only makes sense if the Detox spike passes.

**Must spike locally:**

1. Install Detox 20.51.x on RN 0.72.17. Run 1 trivial test on the iOS 26.5 simulator (Xcode 26.6) and the Android emulator, 20× sequentially. Record build blockers (Detox Android Kotlin/AGP vs RN 0.72's AGP 7/JDK 11) and the flake count.
2. Using Detox's busy-resource log, check whether Firestore/Auth listeners block idle on a logged-in screen.
3. Run Maestro ≥2.11.0 (latest) on the same 20× loop, in two modes: per-flow invocations and one folder invocation. Grep for `DeviceUnreachableException` / `kAXErrorInvalidUIElement` to confirm or rule out #3538 as the local cause.
4. Measure the wall-clock cost and recovery success of an automated recovery wrapper (kill idb_companion/driver + `simctl shutdown/boot`).

## Conflicts & gaps

- **Release years.** WebFetch reported 20.47.0 as "January 26, 2025" and 20.41.0 as "September 2, 2024". Both are implausible: RN 0.83 and 0.79 support could not exist then. Cross-checks (#4828 closed 2026-01-22 via the iOS 26 compatibility PR; RN 0.83's Dec 2025 release) place 20.47.0 in Jan 2026. Treat these years as unverified, and use the npm publish times before citing them.
- **Brief vs evidence.** The brief says #1585 is "open since 2023". It was closed 2026-03-09 without a fix (C6).
- **No independent comparisons.** No independent, quantitative Maestro-vs-Detox flakiness comparison for 2025–2026 was retrieved. The Jupiter Money blog returned 403. The Infinite Red/Ignite "switched to Maestro" claim came from a search snippet only and was not confirmed on the fetched page. The State of React Native E2E-tool numbers were not found. Every flakiness percentage found is vendor marketing.
- **LLM authoring quality.** No evidence was found on LLM authoring quality for Detox TS vs Maestro YAML (C15).
- **Detox + RN 0.72.** No issue or report was found of Detox ≥20.47 running on RN 0.72 (success or failure) (C4).
- **Firebase and Detox sync.** No primary-source evidence was found on whether Firebase listeners defeat Detox sync. Search results were content-farm only and were not used.
- **Maestro `id:` mapping.** Maestro's `id:` selector mapping to the RN `testID` was not verified in this pass.
- **Maestro 2.11.0 locally.** Whether 2.11.0 reduces the local crash rate is untested. Changelog 2.7.0 contains plausible partial fixes (E24), but #3538 still reproduces on 2.11.0 per its reporter.
