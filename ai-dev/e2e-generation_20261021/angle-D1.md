## Verdict per hypothesis

**H1. One-command, fully comprehensive, fully working is unrealistic; the ceiling is a resumable pipeline with a human spec checkpoint.**

- Strongest counter-evidence:
  - Diffblue's claim of a single prompt producing whole-codebase verified regression suites with no developer intervention (C2).
  - AutoE2E's 79% feature coverage from spec-free inference (C17).
  - Autonomous GUI agents creating realistic tasks with no human input (D1-E39).
- How strong: weak to moderate.
  - Diffblue is unit-level Java, vendor-benchmarked, and its tests are verified to compile and pass, which means they lock in current behavior.
  - AutoE2E is a web benchmark score, not a running suite.
  - Every industrial LLM test deployment found (Meta ×2, Duolingo, QA Wolf) keeps a human review or acceptance gate.
  - No credible case was found of one-shot generation of a working, comprehensive mobile E2E suite with no human spec review.
- **Verdict: weakened at the margin, still standing.** One-shot autonomy is credible for unit-level regression (characterization) suites. That is not E2E and not intent-based. The "human spec checkpoint" part could be softened into a "human acceptance or triage checkpoint", since Meta's systems skip a spec but never skip review.

**H2. Environment and harness dominate effort over test authoring.**

- Strongest counter-evidence:
  - EAS Workflows plus Maestro in about 5 config steps (E16).
  - Firebase Emulator Suite seed import/export and `emulators:exec` (E28, E29).
  - Maestro's "one install line … built-in flakiness tolerance" (E30).
  - An HN practitioner saying the pain is not in writing tests (E36). In context this argues maintenance and debugging dominate, which is not the same as environment.
- How strong: moderate as evidence that the plumbing exists, weak as evidence about effort.
  - None of these sources measure setup effort.
  - They don't address third-party stubs (payments, push, OAuth), native-module builds, or iOS simulator flakiness.
  - Robo and the App Testing Agent need manual credential setup (E27, D1-E14).
  - The maintenance-burden figures that would show authoring or maintenance dominating (the Rainforest 55% ≥20 hrs/week figure, the Capgemini "40–60%" figure) could not be fetched from primary sources.
- **Verdict: weakened slightly.** For an Expo + Firebase stack the harness skeleton is close to templated, so the costly part is more likely seeding realistic state, stubbing third parties, and maintenance than the basic emulator/CI wiring. The hypothesis survives for brownfield React Native apps with native modules and external services.

**H3. Code-derived oracles assert current rather than intended behavior, so intent input is needed.**

- Strongest counter-evidence:
  - Meta ACH generates tests that catch a described class of faults from an "incomplete, and even self-contradictory" concern description (E3, E4).
  - Meta JiT reconstructs intent from diffs and found real bugs that would have caused serious failures (E5).
  - GPTDroid found 53 new bugs in Google Play apps, 35 confirmed and fixed (E37).
- How strong: moderate.
  - GPTDroid- and DroidAgent-style bugs are mostly crashes. That is an implicit oracle, not an intent oracle.
  - ACH still takes a short human statement of intent (the concern).
  - JiT works on diffs, where the change itself is the intent signal, and yields 8 true positives of 41 candidates with human triage.
  - D1-S8 actively supports H3: coverage-filtered generators validate existing bugs.
- **Verdict: refined, not refuted.** The intent input can be much lighter than a full behavioral spec: a one-line concern, the diff, or implicit oracles such as crashes, errors, and security-rule denials. That points to replacing a heavy human-authored spec with lightweight intent capture and keeping the human at triage.

**H4. Durable generated scripts plus a run–repair loop beat runtime agents for regression suites.**

- Strongest counter-evidence:
  - Duolingo (a named customer, not the vendor) cut manual regression effort by up to 70% with runtime natural-language GPT Driver tests, written as goal prompts that adapt to UI changes (E31).
  - Quora had non-engineers author tests in Momentic, cutting test execution from 7 hours to 30 minutes (E20, vendor).
  - The GPT Driver founders say scripted tests fail on copy and ID changes (E35).
- How strong: moderate for "runtime agents are viable", weak for "better than scripted".
  - Duolingo replaced manual testing, not a scripted suite, and documents runtime-agent failure modes: going rogue and silently working around bugs (E32, E33).
  - QA Wolf's savings come from human engineers maintaining scripts (E18), which supports scripts plus maintenance labor.
  - The Firebase App Testing Agent is in preview, with a 5-minute cap, scrolling failures, and a quota of 200 tests per month (E14, E15).
  - No head-to-head comparison of maintenance cost between runtime agents and scripted suites was found.
- **Verdict: standing, mildly weakened.** Runtime agents are a credible complement: they are less brittle to copy and layout changes and let non-engineers author tests. But the documented oracle weakness (working around bugs) is exactly the property a regression suite can't have. A hybrid seems defensible: scripted core flows plus an optional agentic exploratory or smoke lane.

**H5. Deterministic static extraction should feed the LLM rather than the LLM reading code.**

- Strongest counter-evidence:
  - Claude Code removed its RAG index in favor of pure grep/glob agentic search, which "outperformed everything else by a lot" (E9, E10).
  - mini-swe-agent scores >74% on SWE-bench Verified with bash only (E25).
  - A 2026 controlled study found a structural index only matched agentic grep on resolve rate and localization (E41).
  - A practitioner pilot found no correctness gain from a code graph (E40).
- How strong: moderate.
  - Cherny's evidence was self-described "vibes" (E11), and the RAG it replaced was embedding retrieval, not deterministic AST or route extraction.
  - The same 2026 study found the index cheaper per solve (E42) and a large localization gain within its own harness, which supports H5 on cost.
  - Agentless (E8) is pipeline-shaped and argues against open-ended agency, not against extraction.
  - SWE-bench is bug fixing, not whole-app behavioral inventory. Enumerating every screen, route, callable, and rule is a recall problem where grep-driven reading may miss items and deterministic extraction is exhaustive by construction. No study on that task was found.
- **Verdict: weakened as stated.** The evidence does not show deterministic extraction improves correctness over agentic reading for localization-style tasks, so "should" is too strong as a quality claim. H5 survives as a cost, recall, and reproducibility argument for inventory-style tasks (route tables, Firestore rules, callable lists), which is untested. Reframe it as: use deterministic extraction for exhaustive inventories, and agentic reading for behavior and semantics.

## Conflicts & gaps

- **DroidAgent numbers conflict:** the search snippet says 317/547 tasks realistic, the fetched abstract says 317/374. Likely different arXiv versions; use the fetched figure with its version noted.
- **Agentless numbers differ by version:** v1 reports 32.67% / $0.68, v2 reports 32.00% / $0.70.
- **No maintenance-share figures from primary sources.** Survey numbers on the test-maintenance burden (Rainforest QA 55% ≥20 hrs/week; Capgemini WQR 40–60%; LambdaTest ~8% on flaky tests) were seen only in snippets or secondary blogs and could not be fetched. This is the main gap for H2 and H4.
- **Diffblue benchmark not verified:** the PDF fetched as unrelated design assets. Only the press release was read, so the 81%/32% figures are vendor-stated.
- **No head-to-head study** of runtime-agent E2E against a scripted E2E suite on the same app (cost, flake rate, defects caught). Every comparison found is against manual testing.
- **No study of E2E generation for React Native + Firebase specifically**, and none for one-shot E2E generation including environment bring-up.
- **The Cherny statement reached us through a secondary outlet.** The primary Latent Space recording was not fetched.
- **Self-report bias:** the Meta sources (S1–S3) are the developer's reports on its own internal tools. Strong venues, but not independent replication.
